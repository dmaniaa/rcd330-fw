# Firmware Diff: Stock VW `5624` (`5624_vw`) vs. ŠKODA `5606` (`5606_skoda` / `7.1.2.2` GP + `DE_CV` Overlay)

Complete static and Ghidra 12.2 decompilation comparison between stock Noname/Visteon RCD 330 VW firmware `5624` (`original-fw/std_plus_pss-6.5inch_5624_VW_PQ_ROW.tar` → `extracted-fw/5624_vw/`, decompiled under [docs/decompiled/5624/](decompiled/5624/README.md)) and ŠKODA firmware `5606` (`original-fw/std_plus_pss-6.5inch_5606_SKODA_DE_CV.tar` → `extracted-fw/5606_skoda/`, all `20` differing core binaries archived under [docs/decompiled/diff-5624vs5606/](decompiled/diff-5624vs5606/README.md)).

## Executive Summary & Build Identification

Like the RCD 780 dump ([diff-5624-vs-rcd780.md](diff-5624-vs-rcd780.md)), `std_plus_pss-6.5inch_5606_SKODA_DE_CV.tar` is a **two-layer image**:

1. **Base Firmware (Layer 1 — Official Visteon `7.1.2.2` GP "SUCCESS" Build, Nov 2016)**:
   - Built **`2016-11-07 22:55–23:00 UTC`** (`2,955` files), with `opt/stdplus.ini` reporting `AP_VER=7.1.2.2`, `CUSTM_PQ=5606`, `CUSTM_MQB=V7071`, `VIPAP_VER=7.1.1.0` (`vipImage.bin` dated `2016-11-08`), `BT_VER=C210`, and `PACK_TYPE=VW_PQ_PSS`.
   - Proven by `opt/md_adapter` DWARF workspace path (`/var/lib/jk/stdplus/workspace/STDPLUS_6.5INCH_HOST_SUCCESS/...` vs. `5624`'s `STDPLUS_6.5INCH_HOST_SOP_ROW_Generate`) and `opt/feature_config.ini` (`PROJECT=GP`, `PLATFORM=PQ`, `BRAND=VW`, `CARLIFE_ATTR=TRUE`).
   - Ships with an earlier **Nov 23–24, 2016 Bluetooth update** (`opt/bt`, `opt/lib/bt/libcidb_sdk.so`, `bt_ac_firm/20161124_UGZZC-X501A_C210_bt_ac_firm.bin`), **Linux `3.0.35-5.1.6-g6498a9a`** (`2016-09-23`, identical `5,809,668` B `vmlinux` size as `5624`'s `5.1.10`), **Apple CarPlay SDK `carplay_std_R5_CD30_Sept30`** (`iAP2 5.2`, `CP_IAP2_R3`), and **Android Auto SDK `AAP_VERSION_5.2.2`** (`2016-08-24`).
   - Byte-identical `u-boot.bin` (`142,576` B), `opt/vmf`, `opt/hal_init`, `opt/lib/libHAL.so.1.0.0`, `opt/lib/libvmf_*`, `opt/camera`, `opt/diag`, `opt/diag_eol`, `opt/screenshot`, and `opt/lib/mirrorlink/*` (`AllGoMLC 7.5.3`) to `5624_vw`.
2. **Community Overlay (Layer 2 — `DE_CV` German Translation & Clean-Flash Patch, 2018–2019)**:
   - Identified by 5 late-dated files inside the tarball: `opt/feature_config.ini` (`2018-01-18`), `bt_ac_firm/20161124_UGZZC-X501A_C210_bt_ac_firm.bin` (`2018-06-13`, byte-identical to `5624`), `script/before_app_update.sh` (`2019-06-02`, inserting `rm -rf /opt/gresfiles/*` so flashing Škoda skin over VW removes leftover VW assets), `opt/gresfiles/img_system_setup_language_select_main_list_item_chinese_checkbox_n_ovg.bin` (`2019-07-08`), and **`opt/hmi`** (`2019-08-01`, in-place `.rodata` German translation patch overwriting Slot 2 `Português (BR)`).
3. **Timeline Relationship to `5624` (`8.8.9.1`)**:
   - Unlike RCD 780 (`8.5.9.7`, a sibling 2018 MQB branch), `5606` (`7.1.2.2`, Nov 2016 GP) is a **strictly older generation** than `5624` (`8.8.9.1`, SOP ROW): `5624` upgrades the CarPlay SDK (`CD30 → CD32`), iAP2 (`5.2 → 5.3`), Android Auto SDK (`5.2.2 → 5.2.3`), Bluetooth (Russian phonebook, MailBox, A2DP coexistence), RACE media indexer, VIP MCU (6 new part numbers, BAP date sync, AM `0x26b` retry), and HMI (8 new `.cpp` modules including SAFE Code and multi-language speller).

### 4.1 Renesas RH850 VIP MCU (`vipImage.bin`)
Full decompilation: [docs/decompiled/diff-5624vs5606/vip/README.md](decompiled/diff-5624vs5606/vip/README.md) (`2,814` functions, `0` failed).

### 5.1 Official `7.1.2.2` vs. `8.8.9.1` HMI Feature Differences

### 5.2 Community `DE_CV` In-Place German Patch (Contrast with RCD 780)
- Both `5624` (`ml_start = 0x02d2`, `222` neutral + `1,975` 5-lang entries) and `5606` (`ml_start = 0x02cd`, `219` neutral + `1,961` 5-lang entries) use the compressed 5-language table `[en_US, zh_CN, pt_BR, ru_RU, es_MX]`.
- In `5606_skoda` (`opt/hmi` mtime `2019-08-01`), community patchers replaced **Slot 2 (`Português (BR)`) directly in-place** with **`Deutsch (DE)`** (`file 0x37bd7f` / `VA 0x383d7f`: `Deutsch (DE)  \x1f\x01\xde`), padding shorter translations with spaces and `\x1f` dictionary backreferences so every subsequent string ID stayed aligned without touching Qt slots (`pBtnLangBRAZIL` remains wired to `1OnBtnLangBRAZILClicked` at `VA 0x3d5b44`) or modifying `FZHT_GB18030.ttf`.
- Contrast this with the RCD 780 `5814` overlay ([diff-5624-vs-rcd780.md](diff-5624-vs-rcd780.md#53-aftermarket-german--5814-localization-overlay-forensic-breakdown)), which instead hex-patched `pBtnLangBRAZIL` to call `1OnBtnLangChineseClicked` (Slot 1), overflowed German strings into Slot 2, and added 41 custom `U+FFxx` whole-word glyphs into `FZHT_GB18030.ttf`.
